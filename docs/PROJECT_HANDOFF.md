## 1. Суть и цель

**DayHub** — собственное персональное Android-приложение пользователя, постепенно превращаемое из панели шести модулей в **автономного персонального помощника**. Он должен сам собирать информацию, подготавливать полезные сводки и уведомлять о важном, но **не совершать рискованные внешние действия без подтверждения**. Цель — реально работающий APK, а не макет, PWA или концепт.

У пользователя **Google Pixel 10 Pro (ARM64/aarch64)**. Он готов давать разумные Android-разрешения и выполнять команды в Termux, но не является опытным разработчиком. Инструкции должны быть простыми, пошаговыми, копируемыми, с проверкой результата каждого этапа. Тон общения — живой, прямой, на русском; пользователь любит быстрый прогресс («газ»), но многочисленные циклы нерабочих патчей уже раздражали его. Не заставлять повторять одинаковые действия без диагностики.

**Бюджет: ноль.** Никаких обязательных платных сервисов, VPS, GitHub Actions, платного API или компьютера. Подписка ChatGPT Plus **не даёт бесплатный OpenAI API** для стороннего APK. Не обещать GPT-функции бесплатно или «интеграцию ChatGPT через Plus» без реального допустимого механизма. Возможны локальные алгоритмы, on-device модели, бесплатные источники данных или явно опциональные платные возможности с согласия пользователя.

## 3. Принципы автономного ассистента

1. DayHub должен быть **проактивным**, но предсказуемым: утренний дайджест, события календаря, существенные изменения погоды, важные новости, позже почта и Telegram.
2. **Отправка писем/сообщений, удаление, публикация и иные последствия — только после явного подтверждения**. Для Gmail базовый режим — создавать/предлагать черновики, не отправлять.
3. Показывать, **откуда взялись данные**, когда обновлялись, и почему пришло уведомление; нужен **журнал действий ассистента**.
4. Личные данные по возможности остаются на устройстве; нет собственного сервера, рекламных SDK и скрытой передачи содержимого почты/чатов третьим лицам.
5. Уважать ограничения Android: **WorkManager не гарантирует точное время**. Нельзя обещать строго 08:00 без дополнительной архитектуры/разрешений.
6. Приоритет — стабильность, разрешения по необходимости, защита секретов и понятные ошибки.

## 4. Реально подтверждённые достижения (по хронологии)

### 0.1 — первый работающий APK
- Собран **локально на Pixel 10 Pro** через Termux/Gradle, установлен через Android «Файлы».
- Отображал шесть кнопок/модулей; погода, календарь и музыка работали.
- Новости сначала не работали из-за настроек XML-парсера Android.

### 0.1.1 / 0.1.2 — исправление RSS
- Ошибки на экране новостей: `http://apache.org/xml/features/disallow-doctype-decl`, затем `http://xml.org/sax/features/external-general-entities`.
- Причина: Android XML-парсер не поддерживал отдельные вызовы `DocumentBuilderFactory.setFeature`.
- Временное решение: перехватывать `ParserConfigurationException` вокруг трёх `setFeature`, включая `external-parameter-entities`. **После этого новости заработали.**
- **Долг безопасности:** игнорирование неподдерживаемых защитных настроек **НЕ гарантирует защиту от XXE**. До работы с более чувствительными источниками внедрить и проверить безопасный RSS-парсер, запрещающий DTD/внешние сущности, или иной подход без уязвимого XML-разбора. Не просто удалить проверки.

### 0.2 — автономность
- Добавлен **WorkManager** с фоновой утренней сводкой (ориентировочное окно **08:00–12:00**, не точное время).
- Экран **«Настройки автономности»**, переключатель сводки.
- Сводка включает погоду и ближайшие календарные события, если разрешения доступны. Новости/Telegram пока не входят.
- Пользователь подтвердил установку и работу экрана настроек, **но не подтверждал регулярную доставку утром в фоне**.

### 0.2.1 — уведомления
- Добавлена кнопка тестового уведомления и исправление системных отступов.
- Пользователь подтвердил: **тестовое уведомление работает**, разрешения на уведомления предоставлены.

### 0.3 — тёмный интерфейс и сводка по запросу
- Новый **тёмно-синий/графитовый интерфейс** с закруглёнными карточками, светлым текстом, голубыми акцентами и правильными отступами от статус-бара.
- Кнопка **«Сформировать сводку сейчас»** запускает **OneTimeWorkRequest** для `DailyBriefWorker`, а не фиктивный текст.
- **ПОДТВЕРЖДЕНО СКРИНШОТАМИ:** версия 0.3 установлена, экран открывается, системное уведомление приходит с реальными данными: `Календарь: 02:00 Daylight Saving Time ends`, `Погода: 4.5°C, ветер 2.2 км/ч`.
- Показанный скриншот: заголовок «Твой день, без лишнего шума», кнопки сводки, настроек, погоды, календаря, новостей, музыки, заглушки Gmail/Telegram.
- **Ограничение:** интерфейс 0.3 построен на программно создаваемых Android `View` (`ScrollView`, `LinearLayout`, `TextView`), **не на Jetpack Compose**. Предыдущий помощник называл Compose целью, но фактический экран — View UI.
- Реальная утренняя доставка **по расписанию ещё не проверена**; доказана ручная задача и системное уведомление.

- **НЕ распаковывать в `/tmp`**: на Android/Termux было `Permission denied`. Использовать `~/dayhub-patches/...` или `$TMPDIR` Termux.

### Сборка и установка (проверенный рабочий маршрут)
```bash
cd ~/dayhub/dayhub-starter
~/gradle-8.11.1/bin/gradle --no-daemon assembleDebug
# ТОЛЬКО если BUILD SUCCESSFUL:
cp app/build/outputs/apk/debug/app-debug.apk \
  ~/storage/downloads/DayHub-current.apk
```
Затем Android **Файлы → Загрузки → APK → Обновить/Установить**. Для обновления поверх существующей версии нужен тот же applicationId и совместимая подпись debug APK. Не удалять приложение без необходимости (возможна потеря локальных данных). **Никогда не копировать старый APK под новым номером после FAILED**.

Проверки:
```bash
java -version
~/gradle-8.11.1/bin/gradle --version
ls -lh app/build/outputs/apk/debug/app-debug.apk
```

**Предупреждение:** Kotlin compiler daemon иногда аварийно завершался на ARM64/Termux; Gradle мог всё же успешно собрать APK, но при реальных ошибках компиляции надо читать строки `e: ... MainActivity.kt:<line>`. `BUILD SUCCESSFUL` — главный критерий завершения сборки, а не отдельное предупреждение daemon.

## 6. Архитектура: что известно, а что нужно проверить

**Фактически установлено/подтверждено:**
- Нативный Kotlin Android-проект на Gradle.
- Главный экран и навигация построены программно в `MainActivity.kt` через Android View API.
- WorkManager и `DailyBriefWorker` для периодических и ручных сводок.
- Android уведомления.
- Погода по геолокации (ранее планировался Open-Meteo; **проверить фактический URL/код в исходниках**).
- Локальный Android Calendar provider/разрешения (проверить фактическую реализацию).
- RSS новости с XML-парсером (источники первоначально: BBC, «Украинская правда», БТА, TechCrunch; **проверить текущие адреса**).
- Запуск YouTube Music через Intent/ссылку (проверить точную реализацию).

**Не считать реализованным без проверки:** Room/SQLite-кэш, полноценный Compose UI, надёжный фоновый RSS-сбор, точный будильник на 08:00, OAuth Gmail, Telegram TDLib, on-device LLM, полноценный AI-ранжировщик, аналитика, журнал действий, автозапуск музыки, уведомления о дожде.

**Предлагаемая целевая архитектура (план, не текущее состояние):**
- `ui/`: Jetpack Compose + Material 3, тема, навигация, карточки.
- `data/weather/`: геолокация, почасовой прогноз, кеш, детектор осадков.
- `data/calendar/`: CalendarContract, фильтрация событий, локальное время и часовые пояса.
- `data/news/`: RSS/Atom, безопасный парсер, резервные источники, дедупликация, важность, локальный кеш.
- `data/gmail/`: OAuth Google, чтение и черновики с минимальными scope; никакой автоматической отправки.
- `data/telegram/`: TDLib, защищённая авторизация/хранение сессии, краткие сводки.
- `domain/brief/`: единая модель сводки и приоритетов, объяснение причин уведомлений.
- `background/`: WorkManager, разумные ограничения частоты, журнал задач.
- `storage/`: настройки, кеш и журнал (DataStore/Room по необходимости).
- `security/`: разрешения, безопасный XML, защита токенов, минимизация данных.

Это **предложение для рефакторинга**, не повод одномоментно переписать работающий проект и сломать его.

## 7. Ошибки и уроки — ОБЯЗАТЕЛЬНО УЧЕСТЬ

### XML/RSS
- Три `setFeature` могли выбрасывать `ParserConfigurationException` на Android.
- Временный `try/catch` восстановил RSS, но не доказал безопасность XML.
- **Не подменять безопасность «ошибка проигнорирована».** Отдельно внедрить и протестировать блокировку DTD/XXE и лимиты на размер/время/редиректы.

### Ошибки патча 0.3
- Сгенерированный патч ошибочно использовал `fillViewport = true` вместо корректного Kotlin `isFillViewport = true`.
- Патч удалил/не перенёс функцию настроек, но вызывал `briefSettings()`; компилятор: `Unresolved reference 'briefSettings'`.
- Предыдущие попытки исправления **не записывали файл**, поскольку скрипт искал несуществующее `showBriefSettings`, и пользователь многократно запускал Gradle без изменений.
- Диагностика `grep -nE 'fun |fillViewport|briefSettings|showBriefSettings' MainActivity.kt` выявила фактическую структуру.
- Финальное исправление: заменить `fillViewport` на `isFillViewport`, добавить реальную функцию `private fun briefSettings()` перед `showHome()`. После этого **0.3 успешно установлен и работает**.
- **Вывод:** нельзя угадывать названия функций. Сначала читать файл и структуру, делать патч с проверками, затем проверять diff/синтаксис/компиляцию. Не перезаписывать `MainActivity.kt` без понимания, какие функции уже есть.

### Android UI
- В 0.1/0.2 заголовки перекрывались статус-баром; в 0.3 исправлено. При будущем Compose UI использовать корректные `WindowInsets`/safe drawing.

### Termux
- `/tmp` не подходит для распаковки, использовать `~` или `$TMPDIR`.
- Не использовать GitHub Actions: блокировка биллинга GitHub; локальная сборка уже доказана.
- Java/SDK/Gradle уже установлены, не заставлять пользователя проходить установку с нуля.

## 8. UX и визуальные пожелания

Пользователь **очень недоволен исходным светлым экраном с огромными серыми кнопками** и прямо попросил сделать нормальный интерфейс: «Мне будет больно каждое утро заходить и видеть его». Он хочет **современный, приятный тёмный интерфейс**, развиваемый параллельно с функциональностью, а не «когда-нибудь потом».

Версия 0.3 уже заметно улучшила вид: тёмно-синий фон, округлые панели, голубые акценты, контрастная типографика. Но это **промежуточный дизайн**. Цель:
- Главный экран как **живой дашборд**, не список кнопок: актуальная погода, ближайшие события, важные новости, статус почты/Telegram, краткая сводка.
- Компактные карточки, понятная иерархия, аккуратные иконки, приятные отступы, минимальное число нажатий.
- Навигация: «Главная», «События/Лента», «Настройки» (концепт, не реализовано).
- Тёмная тема по умолчанию; можно добавить системную тему позднее.
- Отдельный экран/карточка «Что сделал ассистент», время последнего обновления, причины уведомлений.
- Реальные данные вместо фиктивных показателей. Никаких «2 письма» без доступа к Gmail.
- Позже перенос UI на **Jetpack Compose/Material 3**, желательно постепенно, с сохранением работающих модулей.

1. Получить **актуальные исходники именно 0.3** из Termux или репозитория, если они туда синхронизированы. Сохранить backup/commit.

5. Стабилизировать патчинг: резервные копии, проверка версии, идемпотентность, автоматическая компиляция, проверка результатов. Не ломать установленную 0.3.

### P1 — DayHub 0.3.x / 0.4: полезный ассистент
1. Главный экран с **реальными карточками** погоды, ближайшего календаря, топ-новостей.
2. Умная сводка: события с приоритетом, погода на день, начало дождя, важные новости; исключать нерелевантные праздники вроде «Daylight Saving Time ends», если они не важны пользователю.
3. Дедупликация и кеш, статус «обновлено N минут назад», резервные RSS-источники.
4. Управляемые уведомления и тестирование; настройки времени/частоты/категорий, учёт ограничений WorkManager.
5. Журнал действий и понятные причины уведомлений.
6. Продолжить современный UI, возможно Compose, **без одномоментного рискованного переписывания**.

### P2 — Gmail
1. Проработать Google OAuth на Android с нулевым бюджетом: OAuth consent, API scopes, тестовые пользователи/публикация, ограничения Google, хранение токенов.
2. Чтение новых/важных писем, отправитель, краткое содержание.
3. Черновики ответов **только с просмотром и подтверждением**; **не отправлять автоматически**.
4. AI-формулировки без платного API: сначала шаблоны/локальная логика, затем возможная on-device модель при реальной поддержке устройства; честно обозначать качество и ограничения.
5. Не запрашивать `gmail.send`, если отправка не нужна; минимальные права.

### P3 — Telegram full
1. Исследовать TDLib для Android ARM64, лицензию, бинарные сборки, авторизацию и ограничения Telegram API; оценить стоимость в ресурсах и сложность.
2. Пользователь хочет **полную** сводку за **12 часов** и непрочитанные чаты; бот этого не обеспечит.
3. Защищать локальную сессию, не выгружать сообщения на сервер без явного согласия.
4. Дать пользователю выбор чатов/исключений/приватности, не отправлять сообщения автоматически.

### P4 — дальнейшая автономность
- Сигналы о дожде и важных изменениях погоды.
- События календаря заранее, с дедупликацией.
- Новости по значимости (Мир, Украина, Болгария, ИИ), фильтр повторов и шума.
- Сводка Gmail и Telegram после подключения.
- Режимы «утро», «сейчас», «что я пропустил»; прозрачный журнал действий.

**Версионирование — ориентир, а не обязательство:** ранее назывались 0.4 для Gmail и 0.5 для Telegram, но после успешной 0.3 приоритетом стала умная сводка/карточки. Следующий ИИ должен предложить реалистичную последовательность, не привязывая нереализованные функции к обещанной версии.

## 10. Нефункциональные требования

- **Стоимость:** бесплатно в использовании и сборке, никаких скрытых подписок.
- **Платформа:** Pixel 10 Pro, Android ARM64, локальный Termux.
- **Приватность:** локальная обработка по возможности, минимальные permissions, не логировать токены/содержимое личных сообщений, не коммитить секреты.
- **Безопасность:** запрет автоматической отправки, защита RSS/XML, безопасное хранение OAuth/TDLib, контроль сетевых запросов и размеров данных.
- **Надёжность:** offline/кеш, таймауты, запасные источники, явные ошибки, обновление APK поверх предыдущей версии, отсутствие потери данных.
- **Энергопотребление:** не держать постоянный сервис без необходимости, учитывать Doze и ограничения фоновых задач.
- **Доступность:** читабельный шрифт, контраст, правильные системные отступы, понятные статусы.
- **Часовые пояса:** корректно учитывать локальное время и переходы DST; событие «Daylight Saving Time ends» уже попадало в сводку.

## 11. Как работать с пользователем — правила для нового ИИ

1. **Пиши по-русски**, простыми конкретными шагами. Пользователь может прислать скриншот Termux; читать фактические сообщения об ошибках.
2. Не давать десятки команд сразу. На каждом этапе: что вставить, что должно появиться, что делать при ошибке.
3. **Не заставлять заново ставить SDK/Gradle**: всё уже есть.
4. При патче **сначала запросить исходник** или безопасно прочитать через доступный GitHub/файл; если не видишь исходник, дать диагностическую команду, а не угадывать.
5. **Не выдавать ссылки на ZIP/APK, если файл реально не создан и не проверен.** При возможности создавать готовые проверяемые файлы/патчи.
6. После `BUILD FAILED` **не копировать APK**. После успешной сборки проверять файл и устанавливать поверх.
7. Проводить различие между **тестовым уведомлением**, **ручной реальной сводкой** и **доказанной автономной утренней доставкой**.
8. Не обещать ChatGPT API бесплатно только потому, что у пользователя есть Plus.
9. Не навязывать новый стек, сервер или платный сервис. Прогресс важнее идеальной архитектуры.
10. Пользователь хочет, чтобы ассистент был **действительно автономным**, но управляемым и безопасным.
